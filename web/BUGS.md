# Баги веб-интерфейса (форма заказа)

## BUG-01. Поле «Количество» позволяет ввести значение больше 10, нарушая заявленный лимит 1–10
**Серьёзность:** Critical  
**Приоритет:** High  
**Окружение:** Яндекс.Браузер (последняя версия), Windows 11, 1920×1080  
**Раздел:** Форма оформления заказа  

**Шаги воспроизведения:**
1. Открыть страницу формы заказа.
2. В поле «Количество» с помощью стрелок увеличить значение до 99 или ввести «99» с клавиатуры.
3. Заполнить остальные обязательные поля корректными данными (имя, e-mail, дата и т.д.).
4. Нажать кнопку «Отправить» / «Оформить заказ».

**Фактический результат:**  
Поле принимает любые значения в диапазоне от 1 до 99 включительно. Заказ успешно оформляется с количеством 99. Ограничение в 10 единиц не работает ни на клиентской, ни на серверной стороне.

**Ожидаемый результат:**  
Поле должно принимать значения только в диапазоне от 1 до 10. При вводе числа >10 должно отображаться сообщение об ошибке валидации или значение автоматически корректироваться до 10. Стрелки не должны позволять превысить 10.

**Примечания:**  
- [Скриншот с полем 99](screenshots/bug01_quantity_99.png)
- Валидация поля происходит после отправки формы или нажатия Enter. При ошибке в поле появляется красный текст, но здесь ошибки нет – заказ оформляется с некорректным количеством.

## BUG-02. Чекбокс согласия на обработку персональных данных отмечен по умолчанию
**Серьёзность:** Critical  
**Приоритет:** High  
**Окружение:** Яндекс.Браузер (последняя версия), Windows 11, 1920×1080

## BUG-03. Форма отправляется без выбора варианта в радиокнопках «Нужна доп. установка?»
**Серьёзность:** Critical  
**Приоритет:** High  
**Окружение:** Яндекс.Браузер (последняя версия), Windows 11, 1920×1080  
**Раздел:** Форма оформления заказа  

**Шаги воспроизведения:**
1. Открыть страницу формы заказа.
2. Заполнить все обязательные поля, кроме радиокнопок «Нужна доп. установка?» (не выбирать ни «Да», ни «Нет»).
3. Нажать кнопку «Отправить».

**Фактический результат:**  
Форма успешно отправляется, заказ создаётся. Радиокнопки остаются в исходном состоянии (ни один вариант не выбран).

**Ожидаемый результат:**  
Если радиокнопки являются обязательным полем, форма не должна отправляться без выбора. Должно отображаться сообщение о необходимости выбрать один из вариантов, а отправка должна блокироваться.

**Примечания:**  
- [Скриншот с пустыми радиокнопками и успешной отправкой](screenshots/bug03_radio_empty_submit.png)
- Валидация поля происходит после отправки формы. При ошибке должно появляться красное сообщение, но здесь отправка проходит – валидация отсутствует.

## BUG-04. Поле «Дата самовывоза» принимает прошедшие даты
**Серьёзность:** Critical  
**Приоритет:** Medium  
**Окружение:** Яндекс.Браузер (последняя версия), Windows 11, 1920×1080  
**Раздел:** Форма оформления заказа  

**Шаги воспроизведения:**
1. Открыть страницу формы заказа.
2. В поле «Дата самовывоза» с помощью встроенного календаря или ручным вводом выбрать прошедшую дату (например, вчерашнюю).
3. Заполнить остальные обязательные поля валидными данными.
4. Нажать кнопку «Отправить».

**Фактический результат:**  
Заказ оформляется с датой самовывоза, которая уже прошла. Система не препятствует выбору прошлых дат.

**Ожидаемый результат:**  
Поле «Дата самовывоза» не должно позволять выбирать дату ранее текущего дня. При попытке ввода прошлой даты должно появляться предупреждение или выбор должен блокироваться.

**Примечания:**  
- [Скриншот с прошедшей датой](screenshots/bug04_past_date.png)
- Может привести к созданию заказов, которые невозможно выполнить.
- Валидация поля происходит после отправки формы. Ошибка не возникает – валидация отсутствует.

## BUG-05. Поле «E-mail» пропускает некорректные адреса (неполный домен, кириллица в домене)
**Серьёзность:** Major  
**Приоритет:** Medium  
**Окружение:** Яндекс.Браузер (последняя версия), Windows 11, 1920×1080  
**Раздел:** Форма оформления заказа  

**Шаги воспроизведения:**
1. Открыть страницу формы заказа.
2. В поле «E-mail» ввести значение `andrejchenko04@gmail.c` (неполный домен верхнего уровня).
3. Заполнить остальные поля корректно и отправить форму.
4. Повторить шаги 1–3, введя `test@mail.т` (кириллический домен).

**Фактический результат:**  
Форма отправляется, заказ оформляется. Система не проверяет корректность адреса электронной почты.

**Ожидаемый результат:**  
Поле должно валидироваться согласно спецификации RFC 5322. Адреса с отсутствующей точкой в домене (`gmail.c`) или с кириллицей в доменной части (`mail.т`) должны вызывать ошибку валидации, отправка должна блокироваться.

**Примечания:**  
- [Скриншот с некорректными email-ами](screenshots/bug05_invalid_email.png) (коллаж из двух примеров)
- Некорректные адреса приводят к невозможности доставки писем, клиент не получит подтверждение заказа.
- Валидация поля происходит после отправки. Ошибка не возникает – валидация отсутствует.

## BUG-06. Радиокнопки «Нужна доп. установка?» допускают одновременный выбор «Да» и «Нет»
**Серьёзность:** Major  
**Приоритет:** Medium  
**Окружение:** Яндекс.Браузер (последняя версия), Windows 11, 1920×1080  
**Раздел:** Форма оформления заказа  

**Шаги воспроизведения:**
1. Открыть страницу формы заказа.
2. Последовательно нажать на радиокнопки «Да» и «Нет» в блоке «Нужна доп. установка?».

**Фактический результат:**  
Обе радиокнопки остаются выбранными одновременно. Отсутствует стандартное поведение переключателей, при котором выбор одного варианта автоматически снимает другой.

**Ожидаемый результат:**  
Радиокнопки, относящиеся к одной группе, должны работать как взаимоисключающие: выбор одного варианта отменяет выбор другого. Одновременный выбор невозможен.

**Примечания:**  
- [Скриншот с обеими выбранными радиокнопками](screenshots/bug06_both_radios_selected.png)
- Поведение не соответствует спецификации HTML для элементов `<input type="radio">` с одинаковым атрибутом `name`.
- Дефект виден сразу при взаимодействии, не зависит от отправки.

## BUG-09. Кнопка «Назад» на странице успешного заказа не возвращает на форму оформления
**Серьёзность:** Minor  
**Приоритет:** Low  
**Окружение:** Яндекс.Браузер (последняя версия), Windows 11, 1920×1080  
**Раздел:** Страница подтверждения заказа  

**Шаги воспроизведения:**
1. Оформить заказ, заполнив все обязательные поля.
2. На странице с сообщением об успешном создании заказа нажать кнопку «Назад» (если она отображается).

**Фактический результат:**  
Кнопка «Назад» либо неактивна, либо ведёт не на форму оформления заказа (например, на предыдущую страницу браузера или посторонний URL). Вернуться к форме для создания нового заказа с её помощью не получается.

**Ожидаемый результат:**  
Кнопка «Назад» должна перенаправлять пользователя обратно на страницу с формой заказа, позволяя быстро оформить ещё один заказ.

**Примечания:**  
Скриншот не требуется, дефект легко воспроизводится.

**Окружение:** Яндекс.Браузер (последняя версия), Windows 11, 1920×1080
